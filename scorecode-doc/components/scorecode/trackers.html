Referencing trackers

You can reference the contents of other trackers even in a tracker.
To do this, use the "<tracker name>" syntax.
This will usually extract the tracker's stored value. However, if the tracker is a helper tracker, it will functionally be replaced by the code of the helper tracker. The helper tracker code will also be able to reference values in the scope that it was called in, but the names need to match.

If you wish to reference the tracker that the code is hosted on, do not use this syntax, instead use the 'value' keyword.

Tracker resolve order

When multiple trackers have the same trigger method, when the trigger fires and updates the value of all subscribed trackers, the trackers are updated according to their dependencies. This is to prevent referencing stale values.
When a tracker contains a reference to another tracker, that tracker is added to the tracker's dependency list. A tracker will only update after all of its dependencies have already updated.
Tracker references to trackers that do not share the trigger method will not enter the dependency list.
Otherwise, there is no strict resolve order and trackers on the same dependency level can be updated in an arbitrary unknown order.

Circular dependencies

Circular dependencies are not allowed in Scorecode. If a circular dependency is found the trackers will not update and you will receive an error notification whenever it attempts to update.
Note that the dependency list is not smart; if a tracker reference another tracker at all the tracker will be added to the dependency list, even if the tracker reference is skipped in execution (such as via branching code).
