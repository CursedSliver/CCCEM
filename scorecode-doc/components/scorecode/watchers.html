Watchers

A Watcher is a set of pieces of code that returns specific information about the state of the game at the time that it is called.
Each Watcher returns a specific piece of information, such as cookie count, golden cookie count, CpS, etc. Watchers are fixed and cannot be modified; Watchers cannot be added or removed.

Watchers are called by the [<watcher name>] syntax.

Argument passing

Notably, some watchers can accept arguments. For example, the "buff index" watcher can be called with the name of the buff to check for its index in the buff list, if it exists.
The description for a watcher will usually mention arguments that can be passed to it.

To pass arguments to a watcher, put them inside the square brackets separated by semicolons with the first being the watcher name, like so:

[<watcher name>;<argument 1>;<argument 2>] (the amount of arguments are not limited to 2)

Usually the argument is NOT interpreted as code; the argument is passed to the Watcher handler directly as string, or a number if it can be parsed as a number.
To make the game interpret the argument as code and execute it to pass the output to the Watcher, you need to put a $ before the argument, like so:

[<watcher name>;$<executed code>]

Examples

The examples below use placeholder watcher names; substitute the actual watcher you want. The brackets and semicolons are part of Scorecode syntax.

A watcher with no arguments - just the name in square brackets. This is the most common form.

[[codebox:[bank] // returns the player's current cookie bank balance [cookiesps] // returns the player's cookies-per-second (CpS) [golden] // returns the number of golden cookies on screen [wrinklers] // returns the number of wrinklers spawned // All of the above return a number that can be used like any other // numeric expression. [banks] + [wrinklers] // sum of the bank and the wrinkler count [banks] > 1000 ? 1 : 0 // 1 if the bank is over 1000, else 0]]

A watcher with a string argument - arguments are separated by semicolons. Most arguments are passed as raw strings, not code.

[[codebox:[buff;building] // 'building' is passed as the string "building" [hasbuff;frenzied] // 'frenzied' is passed as the string "frenzied" [buildingprice;cursor] // 'cursor' is passed as the string "cursor" // You can compare a watcher result to a number the usual way: [hasbuff;frenzied] = 1 -> 1 if the Frenzy buff is active, else 0 [buildingprice;cursor] - [buildingprice;grandma] // difference in price // between the cursor and grandma buildings]]

Passing a number as an argument - if an argument parses as a number, it is passed as a number (not as the string of the number).

[[codebox:[upgrade;7] // the upgrade at index 7 [building;0] // the count of the building at index 0 (cursor) [building;1] // the count of the building at index 1 (grandma) // Use a number argument to look up by index: ([building;0]) > 100 // 1 if you own more than 100 cursors, else 0 [building;0] + [building;1] // total owned cursors + grandmas]]

Passing an executed Scorecode expression as an argument - prefix the argument with $ to make it run as Scorecode and pass the result.

[[codebox:[building;$0] // same as [building;0]: runs 0 -> 0, passes number 0 [building;$1 + 2] // runs 1 + 2 -> 3, passes number 3 to the watcher [building;$[building;0]] // runs [building;0] to get the cursor count, passes that // Without the $, the inside of the brackets is just a string, so this // would NOT execute the inner [building;0]: [building;[building;0]] // 'building' is the watcher, '[building;0]' is a string // // argument. This is almost certainly not what you want; // // use $[building;0] instead to execute the inner code.]]

Combining watchers with normal expressions - watchers are just numbers, so they compose freely with everything else.

[[codebox:[cookiesps] * 60 // estimated cookies earned in 60 seconds [banks] / [cookiesps] // seconds of CpS the bank can sustain [golden] + [wrinklers] // total special cookies on the screen [golden] > 0 ? [cookiesps] : 0 // CpS only when a golden is on screen, else 0 [banks] > 1000000 ? 1 : 0 // 1 once the bank passes 1 million, else 0 [banks] min [target] // the smaller of the current bank and a tracker named "target"]]
